# TASKS.md

Task types and what each one owes the user.

## Research / information
Deliverable: ONE well-formatted document (.md) — findings, sources, and
clear limits of confidence. Cross-check claims across independent sources
(see RESEARCH.md). The document is the product; the chat summary is its
abstract.

## Build: site / app / script project
Deliverable: ONE .zip containing the complete project (source, assets,
README with run instructions, lockfile). Works-after-unzip is the bar:
verify it runs before zipping (see skills/fullstack-web-app or
static-landing-page). Never deliver loose members next to the archive.

## Build: single-file tool
A single script or single HTML file that genuinely stands alone → deliver
the file itself. If it grows a second file, it's a project — zip it.

## Data work
Deliverable: cleaned data + analysis + charts + a short written report.
Charts as files (PNG) inside the project folder; the report explains the
numbers in sentences (see skills/data-analysis).

## Document writing
Deliverable: the document — one file, in the user's language, structured
with headings, no filler (see CONTENT.md).

## Conversation / explanation
No file needed. Answer in chat — direct, grounded, honest about
uncertainty. Do not create a file nobody asked for.

## Mixed tasks
When a task is "research then build", both halves apply: evidence while
researching, the archive when building. The final summary covers both.
